# 单场景任务与评测设计

日期：2026-11-17。状态：拟议方案，尚未实现任务集、独立评分器或真实模型评测。

## 1. 选题与首轮范围

选题建议：视觉异常驱动的产线设备诊断与闭环处置。

研究问题：出现视觉质量异常时，Agent 能否通过补充观测、设备知识与受约束干预完成恢复验证，或正确停止、移交？

用户已确认先跑通一个场景，再扩大兼容性。首轮使用点胶胶路覆盖不足；灌装留作第二场景适配验证。多 Agent 的收益通过对照实验判断；光学后端另设感知任务，不作为首轮闭环前提。

先验证三项能力：取证能否减少无效维修；维修无效后能否依据反馈调整；动作结果不确定时能否避免盲目重复。当前固定阈值规则已能解决十个回归用例，不能仅通过增加角色数量证明 Agent 必要性。

## 2. 一次任务是什么

一次任务是一条完整异常处置事件，不是一次分类或工具调用。

示例任务描述：

> 点胶工位出现胶路覆盖不足告警。请核实异常，在允许动作与预算内处置；依据动作后的新证据判断恢复情况。无法恢复时按任务约束处理设备状态，并提交有证据的工单。

Agent 可见设备身份、告警、公开观测、手册和能力；隐藏原因、动作实际效果与预期判定条件只对环境及评测器开放。正确性由允许的结果与约束定义，不能只匹配唯一动作脚本。

## 3. 六类任务

| 编号 | 任务族 | 拟构造条件 | 核心判据 |
| --- | --- | --- | --- |
| G01 | 告警核实 | 旧告警、正常波动或当前已正常 | 获取可信新证据；避免不必要维修 |
| G02 | 同症异因 | 覆盖不足分别来自堵塞、供料不足 | 根据有区分力的观测选择对应动作 |
| G03 | 观测退化 | 污染、曝光或图像异常 | 先检查测量可信度，不把坏观测直接当工艺故障 |
| G04 | 复合故障 | 观测退化与真实工艺故障共存 | 一个问题消除后继续复测，直至正确终态 |
| G05 | 维修无效 | 命令接受但缺陷持续 | 不误报恢复；停止无效尝试并正确移交 |
| G06 | 执行不确定 | 超时、回执丢失或进程中断 | 查询动作或明确未知；不盲目重做写操作 |

G01-G05 评价运维决策；G06 评价运行可靠性，分别报告。复合故障、曝光变化、动作状态查询等为待实现能力；当前 v0.1 不具备上述全部条件。

“同症异因”需要真实歧义：初始信息不能直接编码答案，补充观测应有可解释的区分能力。先定义测点及动作因果，再决定是否增加独立压力查询、历史数据或相机检查工具。不能靠改工具名制造难度，也不能让不可辨识的原因必须被精确猜中。

## 4. 任务卡契约

每张任务卡在实现前写明以下字段：

| 字段 | 必须明确的内容 |
| --- | --- |
| 身份与版本 | task_id、任务族、场景版本、设备身份、生成参数和种子 |
| 初始条件 | 告警、设备状态、公开证据、时效和质量 |
| 私有真值 | 原因、可修复性、动作因果、独立完成条件 |
| 可用能力 | 观测、手册、允许动作、参数与权限 |
| 动作约束 | 暂停要求、版本、有效期、幂等键及结果查询能力 |
| 允许终态 | 恢复、移交、停止各自需要的证据和设备状态 |
| 成本与预算 | 工具、模型用量、实际耗时；模拟时间和代价另列 |
| 扰动 | 注入点、超时语义、缺失和噪声如何影响环境 |
| 评分 | 正确结果集合、禁止行为、失败理由与评分器版本 |

私有参数不能经文件名、工具结果、提示词或公开工单泄露。任务可以有多条正确处置路径。恢复完成应要求质量与设备状态满足场景条件；移交应有证据和未解决事项。任务停止与设备暂停分别记录，不能互相替代。

当前覆盖阈值和供压值属于简化模拟量；尚无真实物理单位和现场标定。未来采样间隔、连续合格窗口和失效模式需要依据场景定义，不把三张新帧当作统计置信度。

## 5. 运行约束与评分分离

运行内核检查权限、动作前置条件、预算及其自身恢复谓词。独立评测器检查任务真值、真实状态变化、完整轨迹、证据有效性和允许终态。

不能直接把事件的 `status == recovered` 当成得分。评测器应能识别运行器判定错误，包括测量失真、陈旧证据、未解决复合故障和错误设备身份。使用单独的评分逻辑；评分器能访问私有状态，Agent 不能。

对模拟环境，评分器可以依据私有世界状态和独立结果检查。未来真实现场需要独立测量或人员确认，不能假设现场有可读取的根因真值。

## 6. 指标与对照

主要结果分别统计：正确恢复、正确移交、正确停止、失败和不必要移交。正常检查通过不计为成功维修。

同时报告：

- 误报恢复：宣告恢复但独立条件不满足；同时给出事件数和分母。
- 无效或错误维修：区分命令被接受与实际改变状态。
- 禁止动作尝试和实际违规执行：网关拦住错误仍属于策略错误。
- 重复状态变更、执行结果未知及未解决事项。
- 工具次数、模型用量、实际耗时与可取得的费用；未知项标为 unknown。
- 模拟停机时间和代价：只有明确定义并实现代价模型后才报告，与真实墙钟耗时分开。

对照组：现有规则、单 Agent、诊断/规划/验证三角色。使用相同任务、工具语义、动作网关、终态标准和总工具预算；单 Agent 获得完成任务所需工具的合理并集。模型用量设总体上限并报告实际值；固定复核开销统一计入。

后续可做补充观测和强制复核的消融。取消运行时复核仅限隔离沙箱，独立评分仍保留；消融比较以相同任务为基础。

## 7. 数据划分与实验冻结

1. 保留已有十任务作为功能回归，不用它们推断工业维修成功率。
2. 先为六类任务建立少量开发案例，验证可解性、扰动效果、工具协议和费用。
3. 依据初测成本，在正式实验前确定任务数、模型配置、总体预算和重复次数。
4. 按故障组合、设备配置、参数区间及观测条件分组划分开发和保留集，避免仅换种子的近重复任务泄漏。
5. 冻结场景、任务、评分器与策略版本后运行；调试过的失败案例进入开发或回归集，另建新的保留集。
6. 保留全部失败轨迹，按任务族报告，并记录配对结果和适当的不确定性；重复模型调用不当作独立任务样本。

灌装的迁移评测在点胶通过阶段验收后进行。预先声明允许修改的是适配器、知识和阈值，还是也允许重调提示词；如果修改策略，区分重新适配效果和未经调参的迁移效果。

## 8. 管线与首轮交付

目标管线：任务加载 → 环境复位 → 策略执行 → 独立评分 → 轨迹归档 → 汇总报告。

归档至少包含 task_id、场景和代码版本、策略/模型/提示词版本、种子、预算、原始观测、动作请求、回执、状态变更、终态、独立得分、耗时和用量。原始证据与报告关联，原始模型输出在提交前检查敏感信息。

首轮交付顺序：六张任务卡及动作因果 → 可复现环境和独立评分器 → 规则基线 → 真实模型点胶轨迹 → 中断与重放验证 → 冻结保留集后的对照报告。实施验收见 [M2 计划](m2-plan.md)。
