# 自动化实验室：可迁移的系统设计

整理日期：2026-11-17。状态：文献调研与 LineOps 设计建议，未复现这些系统。

核心问题：一次动作如何进入设备、产生可信的结果证据，并影响下一步决策？以下内容按来源描述和迁移建议分开记录。核验深度与访问限制见 [来源目录](sources.md)。

## 1. ChemOS 2.0：模块边界与错误注入

来源：[LAB-01](sources.md#lab-01-chemos-20)。*ChemOS 2.0: An orchestration architecture for chemical self-driving laboratories*，Matter，2024。

来源内容：模块化编排负责组件通信、数据交换与指令管理，将规划、仪器和数据连接起来。作者代码包含 `ChemOS2.0-simulation-errors` 和 `ChemOS2.0-simulation-parallel`，用于设备错误及并行工作流演示。仓库说明代码需要按实验定制，不是可直接部署的完整产品。

LineOps 建议：

- 分开策略、运行内核、设备适配器和证据存储；策略通过稳定对象调用设备能力。
- 点胶先实现最小边界，记录新增灌装适配器时实际修改了哪些核心代码。
- 借鉴错误模拟的组织方式，加入动作超时、设备异常和服务中断测试。

边界：错误处理示例不证明崩溃后动作不重复；我们的账本、检查点和状态核对仍需独立验收。

## 2. HELAO-async：工作流与设备资源分离

来源：[LAB-02](sources.md#lab-02-helao-async)。*Orchestrating nimble experiments across interconnected labs*，Digital Discovery，2023。

来源内容：多个实验流程独立启停并共享设备资源，使用 Python 异步编程和 FastAPI 服务组织实验设备及编排。

LineOps 建议：将任务身份、设备身份、执行状态和资源占用分别建模。先支持单设备任务查询与停止，再扩展多工位、共享相机及维修资源；工作台读取执行中状态不应等待任务结束。

边界：异步执行本身不提供跨进程互斥、物理动作幂等或实时性保证。本轮出版社正文访问受限，具体实现需结合公开全文或代码进一步核查。

## 3. AlabOS：任务、资源所有权与异常处置

来源：[LAB-03](sources.md#lab-03-alabos)，Yuxing Fei、Gerbrand Ceder 等，2024 年预印本。

来源内容：将实验组织为模块化任务，使用资源预约协调并行工作流；设备管理检查资源所有权。异常处理区分可恢复和不可恢复情形，并支持重试、人工介入或任务失败。

LineOps 建议：

- 每个任务保存阶段、设备与资源所有权、失败原因及下一步允许操作。
- 区分可重试的只读失败、执行结果未知的写操作、明确失败的维修，以及需要人工处理的故障。
- 人工介入保存触发证据、原因、设备状态和未完成操作，作为正式终态或等待状态。

边界：已读材料不足以证明任意进程崩溃后恢复，更不足以证明真实设备 exactly-once。执行结果未知时先查询，无法查询则停止或移交。

## 4. Coscientist：设备文档、工具与反馈

来源：[LAB-04](sources.md#lab-04-coscientist)。*Autonomous chemical research with large language models*，Nature，2023。

来源内容：语言模型结合文献和设备文档检索、代码执行及实验自动化工具，组织实验规划、执行与分析。

LineOps 建议：模型围绕手册、公开观测和真实工具返回值决定下一步。保存模型与提示词版本、工具参数、回执、证据身份、耗时及可取得的用量；未知费用标为 unknown。允许模型推理，权限、前置条件和终态检查由运行内核执行。

边界：接通 function calling 只证明协议可用；需要真实模型在冻结任务上的轨迹，才能评价闭环效果。

## 5. XDL / Chemputer：任务语义与设备实现

来源：[LAB-05](sources.md#lab-05-xdl--chemputer)。*A universal system for digitization and automatic execution of the chemical synthesis literature*，Science，2020。

来源内容：把合成过程转为可编辑、可编译执行的描述，连接到自动化合成系统。

LineOps 建议：区分“采集新观测、暂停、维护、恢复、验证”等任务语义，以及设备具体 API、单位、能力和前置条件。适配器声明可用能力；不支持的动作必须明确拒绝。

边界：借鉴中间表示与执行分层，不将化学过程语言直接当作工业运维通用协议。新增设备仍需实现和验证动作因果关系。

## 6. A-Lab：动作之后的独立结果证据

来源：[LAB-06](sources.md#lab-06-a-lab)。*An autonomous laboratory for the accelerated synthesis of inorganic materials*，Nature，2023；该工作另有作者更正。

来源内容：连接方案提出、机器人实验、XRD 表征和后续实验选择，通过测量反馈调整后续方案。

LineOps 建议：分别保存命令、执行回执、动作后观测和结果判定。清理动作 accepted 之后仍可能未恢复；模型需要据此重新取证或移交。恢复判定引用新证据和设备状态，不能只引用模型文字。

边界：引用成果数字前核对更新版和更正。本知识库不沿用材料合成成功数字，也不将其迁移成维修成功率。评测器应独立检查运行器的终态。

## 7. ORGANA：目标澄清、感知反馈和人在环

来源：[LAB-07](sources.md#lab-07-organa)。2024 年预印本；Matter 正式卷期为 2025。

来源内容：结合自然语言交互、规划、视觉反馈和机器人实验操作，支持目标澄清、任务调度及实验日志。

LineOps 建议：将用户目标形成任务约束与允许终态；信息缺失时区分“继续补证据”和“需要人工确认”。执行中反馈设备、任务与未确定事项，工单保留可供人工接续的证据。

边界：机器人执行与化学实验条件不同于设备维修；人在环是受支持的处置路径，不能通过排除人工来定义自主性。

## 落到第一条点胶闭环

| 借鉴方向 | 最小产出 | 对应验证 |
| --- | --- | --- |
| ChemOS / XDL 的分层 | 稳定的观测、动作、回执与验证对象 | 点胶核心不依赖设备 API 细节 |
| HELAO / AlabOS 的运行管理 | 可查询的任务阶段、设备状态、动作账本 | 中断后核对状态；不盲目重复维修 |
| Coscientist 的工具使用 | 真实模型调用手册、观测和允许动作的轨迹 | 区分模型选择与规则对照 |
| A-Lab 的结果反馈 | 动作后新测量与独立评分 | 维修无效时不误报恢复 |
| ORGANA 的交互与接续 | 有证据的停止或工单移交 | 未确定状态可由人工接续 |

建议先读 AlabOS 和 ChemOS 错误示例，再读与视觉处置相邻的 [制造研究](industrial-landscape.md)，最后用 [任务卡](evaluation-design.md) 明确需要什么能力。以上均为建议，未新增实现或实验结果。
