# M2 推进与验收：先完成点胶闭环

日期：2026-11-17。状态：待执行。依据：用户确认的单场景优先方向，以及 [NEXT_STEPS](../NEXT_STEPS.md) 的工作包。

## 当前起点

v0.1 已有点胶/灌装模拟、像素测量、规则路径、动作约束、强制复核和 SQLite 证据。真实模型只有协议 mock；没有本项目真实模型效果报告。动作回执在内存，重启不能恢复世界。FUXA/MQTT 和光学任务仍有独立验证工作，详见 [STATUS](../STATUS.md)。

此处调整近期交付顺序：先定义和验证点胶任务及评测，再完成真实模型和最小恢复；第二产线作为随后检验兼容性的任务。完整平台愿景继续保留。

## 阶段 A：冻结最小任务定义

交付六张 [任务卡](evaluation-design.md)，定义公开观测、私有原因、动作效果、可用能力、设备状态要求和独立评分条件。

退出条件：同症异因有可用证据区分；错误动作能产生无效结果；不可恢复任务有正确结束方式；不存在故障标签泄漏。先确认环境可表达这些条件，再扩展工具。

## 阶段 B：建立环境、评分与规则基线

实现任务加载、复位、种子、必要的复合故障和扰动，以及独立评分器。保留现有十用例回归，记录规则对照在新增条件下的结果。

退出条件：同一任务可重复执行；扰动确实影响环境或工具；评分器能捕获错误宣告恢复；正常检查与维修结果分开。脚本实现的规则对照必须标明，不记为模型效果。

## 阶段 C：接入真实模型

先跑通单 Agent 的观测、手册、动作和复核，再比较现有三角色。真实运行需可用模型端点、运行时密钥、工具调用支持和明确预算。

退出条件：正常、可恢复及持续故障各有真实模型轨迹；错误维修后能够重新判断；所有结论可追溯到真实返回值。记录模型/提示词/工具版本、耗时、用量与未知费用。

密钥仅通过运行环境提供，不提交到知识库、任务或轨迹。缺少端点时保留 mock 测试，明确尚未完成真实模型验收。

## 阶段 D：把最小恢复能力提前

实现可查询任务状态、持久化动作账本、结果查询和模拟世界检查点。账本保存 action_id、设备/场景身份、参数摘要、前后版本、执行状态、回执及相关观测。

分别注入：执行前中断、状态变更后回执落盘前中断、回执保存后进度保存前中断、相同请求重放及进程重启。

退出条件：相同请求能返回已知结果；参数冲突被拒绝；已确认动作不重复改变状态；执行结果未知时查询或明确停止/移交。证明的是规定故障模型下的行为，不宣称跨真实设备 exactly-once。

任务停止、设备暂停与紧急控制分别建模。真实设备的控制和联锁能力需另行验证，不能套用模拟器检查点。

## 阶段 E：冻结实验并形成报告

依据试运行确定任务规模和重复次数，冻结保留集、评分器与预算，比较规则、单 Agent、多角色。必要的消融随后进行。

退出条件：保留全部失败案例；按任务族报告正确终态、误报恢复、错误动作、重复变更、耗时和费用；没有用角色数量或十个固定用例替代效果证据。

## 阶段 F：再验证兼容性和工作台

将稳定的点胶场景封装为适配器，再接灌装。明确能力、参数、单位、观测质量、动作语义和恢复条件，记录改动范围与适配成本。核心运行器只保留共用职责。

随后实测 FUXA/MQTT，展示执行中状态、证据与终态，检验过期/重复消息及断线重连。光学固定特征任务单独比较同任务数字参考和误差影响，不阻塞点胶闭环验收。
