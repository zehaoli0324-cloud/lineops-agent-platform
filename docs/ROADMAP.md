# 分阶段研发路线

## 已完成：M0 / M1 首版闭环

两仓库、HTML 架构与 Proposal、详细契约、固定第三方源码；两种软件产线、独立像素测量、受控动作、运行事件与 SQLite 证据、工单移交、浏览器入口、离线对照与模型工具协议测试。实现范围及测试结果见 STATUS.md。

## 下一阶段：M2 真实 Agent、场景适配与可恢复闭环

2026-11-17 细化方案见 [NEXT_STEPS.md](NEXT_STEPS.md)，参考文献与模块映射见 [AUTONOMOUS_LAB_REFERENCES.md](AUTONOMOUS_LAB_REFERENCES.md)。这是实施计划，尚未验收；当前实现仍以 [STATUS.md](STATUS.md) 为准。

本阶段分为五个工作包：WP1 真实模型与可比对照、WP2 点胶/灌装适配契约、WP3 最小可恢复执行、WP4 FUXA/MQTT 实测、WP5 光学固定特征任务。先落地场景最小协议并运行真实模型基线，再完成动作账本、检查点与中断验收；工作台随后联通，光学任务保持可选。将 M3 的最小恢复能力提前，多设备和跨进程资源协调继续留在完整 M3。

核心验收是：真实模型点胶处置轨迹、复用运行核心的灌装适配器、中断后不重复执行已接受动作的恢复测试。比较规则、单 Agent、多角色时固定输入、工具与终态判据，记录预算和真实消耗。已有十任务是功能回归；独立保留任务覆盖噪声、过期观测、超时、无效维修与未见条件。正常状态检查、恢复、移交和停止分别统计，不看见结果后调整同一保留集阈值。

工作台须完成真实 broker 与 FUXA 工程验证，并展示执行中状态，处理断线、重复、旧消息与 null 测量。光学路径须在同一输入编码、变换与读出下和 NumPy 参考比较，形成任务质量、扰动与回退报告；独立矩阵功能检查不视为工业视觉或硬件性能验证。

## M3 可恢复运行管理

将同步任务改为队列：queued → running → verifying → terminal；加入暂停/继续、租约、心跳、跨进程锁、过期回收和世界检查点。工作台读取与设备执行解耦。动作 ID 与回执持久化，重启后查询执行状态，避免盲目重试。按设备拆队列，再增加人员、备件和停机窗口资源预约。退出条件是注入中断后可恢复，重复运行不重复维修。

## M4 数据与真实性

增加时间驱动过程、连续视频、噪声、照明变化、局部遮挡、时间戳延迟、缺帧与单位；外部分割／检测模型采用同一 Measurement 契约。建立校准数据与保留集，测试未见故障与传感器冲突。优先复用 PLC 的电流、扭矩、温度、压力与流量，再按设备经济价值增加振动或热像。声学和 3D 各自需要采集设备、标定、任务适配与验证。

## M5 真实只读试点与业务接入

一个设备族、一条线开始：设备语义、采样质量、事件关联、历史工单、人工处置与复核结果。先测人工与辅助流程的排查时间和误告警，再评估动作授权与业务系统写入。30 场景目录逐项获得数据、适配器和验收结果后才标记支持；不使用无法定义分母的领域覆盖率。

## 比赛轨道

比赛仓库以正式规则为准，在窗口内独立实现 P0：点胶自主工作流与证据；P1 灌装切换、光学小任务和 FUXA 画面按稳定性取舍。完整项目研发与比赛原创代码分别记录，不把赛前原型直接复制为参赛作品。
