# LineOps Agent Platform 完整项目规划

版本 3.1 · 2026 年 11 月 15 日 · 完整产品与研究规划 · 尚未实现验证

## 1 项目摘要

LineOps Agent Platform 是面向工业产线的模块化智能设备运维系统。它将多源感知、设备知识、运行管理、多 Agent、业务工具和执行后验证组织为统一平台，逐步覆盖异常发现、核实、诊断、处置、维修协调、恢复验证及知识积累。

完整项目保留多产线、多设备、多模态、不同计算后端和真实业务系统适配的长期规划。黑客松只验证其中一条可交付的工作流，不以比赛的 72 小时限制缩减完整产品目标。

已采用的技术方向是 FUXA 产线工作台、独立有状态软件产线模拟器、运行管理与多 Agent 服务，以及可替换的 Neuroptica 光学计算功能仿真后端。视觉、压力、流量与设备日志优先接入；振动、温度、热像、声学、三维和油液等按设备族扩展。

本文件为规划，不宣称已有客户、已通过场景、已实现自动维修或实体光学芯片性能。比赛专用方案位于独立仓库 lineops-agentware-2026。

## 2 用户和业务问题

目标用户包括设备工程师、产线主管、维护团队、设备厂商和系统集成商。典型工作是接到告警后寻找设备位置、查询历史和过程参数、核实传感器、尝试允许的检查、协调资源、执行处置并记录结果。

平台要验证的业务假设是：跨系统取证耗时、告警与维修结果脱节、相似设备重复定制，以及维修资源冲突会增加处置成本。真实发生频率、现有工具缺口、集成难度和付费意愿需要后续访谈与试点。

| 价值方向 | 需要收集的证据 | 不应提前承诺的结果 |
| --- | --- | --- |
| 缩短排查 | 人工与系统处理同类事件的步骤和耗时 | 未测量的节省比例 |
| 减少停机与废品 | 工位、产量、不良与处置结果的对应记录 | 通用回本周期 |
| 降低接入成本 | 第二条线的实际工时、配置和新增适配器 | 所有设备仅改配置可用 |
| 改善维护安排 | 人员、备件、停机窗口与等待影响 | 未验证的最优调度收益 |
| 节约能源 | 修前修后流量、功率与运行时间 | 直接套用其他工厂的节省率 |

## 3 产品目标和工作闭环

共用闭环是发现事件、核实观测、补充证据、提出并检验假设、比较处置方案、执行允许动作、验证新状态和归档经验。

一次任务的正确终态可以是已恢复、已完成分诊并移交维修，或因证据与权限不足而终止。三类结果分别记录。告警确认、工单创建和工具成功回执都不自动等于设备修复。

完整系统首先服务视觉与过程数据驱动的软件处置。实体拆装、带电检修、计量校准、控制安全功能和其他专用维修工作，需由相应设备、人员和流程承接。

## 4 总体架构和模块边界

| 层次 | 共用职责 | 主要插件或适配点 |
| --- | --- | --- |
| 工作台 | 资产与产线视图、趋势、告警和任务进度 | FUXA；后续其他工作台 |
| 接入层 | 设备标识、采样与接收时间、质量和连接状态 | 图像、视频、PLC、日志、传感器与业务 API |
| 感知层 | 检测、分割、测量、跟踪及信号特征 | 不同任务、模型与标定配置 |
| 计算后端 | 能力声明、计算、质量检查、回退 | CPU、GPU、其他运行时、光学功能仿真 |
| 事件证据层 | 关联设备、工位、时间和来源 | 设备拓扑、工位与产品映射 |
| 知识层 | 手册、故障树、历史案例与适用条件 | 不同设备族和工艺知识 |
| 运行管理 | 生命周期、队列、健康、预算和恢复 | 单机到多节点运行策略 |
| Agent 层 | 按需诊断、规划与验证 | 模型、角色、工具权限和调用预算 |
| 动作层 | 权限、前置条件、有效期、幂等和执行查询 | 模拟器、设备、工单、备件和排程 |
| 验证层 | 依据动作后新观测判断终态 | 各场景恢复与移交标准 |
| 评测层 | 保留任务、回放、对照和失败分析 | 场景套件、预算和评价指标 |
| 治理层 | 版本、审计、数据管理和发布约束 | 工厂权限、数据保留与模型发布 |

工作台显示运行状态；模拟器或真实设备提供状态反馈；运行管理组织执行；Agent 选择需要判断的检查和方案。层间通过稳定对象交互，避免把业务逻辑写入工作台画面。

## 5 FUXA 工作台

采用 FUXA 的工业过程可视化与设备连接能力，配置产线总览、设备详情、过程参数、告警、维修进度与趋势。[FUXA 官方仓库](https://github.com/frangoteam/FUXA) 和 [官方文档](https://frangoteam.github.io/FUXA/) 提供现有能力说明。

Agent 的图像证据、分割结果和执行轨迹放在独立页面，可与 FUXA 并排或通过链接访问；后续再评估统一门户。首阶段优先配置现成工具，不重写 FUXA 核心。

状态通过本地 MQTT 发布订阅连接工作台，Agent 动作经运行服务的受控 HTTP 工具入口执行。FUXA 初期只读；人工操作后续也应经过同一动作网关。告警确认与恢复验证分别表示。

## 6 产线模拟器和验证环境

采用自建轻量 Python 有状态模拟器。它维护设备、过程、资源和隐藏故障状态，产生图像、波形或参数观测，并对动作给出有因果关系的反馈。当前没有指定另一款现成通用产线模拟软件。

模拟能力分阶段发展：先支持状态与离散事件，再支持参数化图像和信号、历史回放、更多传感器及资源约束，之后探索与真实设备或专用仿真环境连接。不同阶段标明物理保真度，不能将简化环境称为已验证的工业数字孪生。

| 模拟模块 | 规划能力 | 必要条件 |
| --- | --- | --- |
| 世界状态 | 运行、阀门、工位、缓存、压力、流量与产量 | 单一权威状态和可复位机制 |
| 故障模型 | 堵塞、供料、漂移、泄漏与观测退化等 | 因果关系限定在具体场景和测点 |
| 观测生成 | 图像、视频、过程参数、日志及后续其他模态 | 保留噪声、缺失和时间关系 |
| 动作反馈 | 测试、切换、维护、工单和资源预约 | 错误动作可以无效；有效动作有时间与资源代价 |
| 私有真值 | 原因、注入参数、预期终态 | 评估端可见，Agent 不可见 |
| 复现回放 | 场景版本、种子、动作与观测记录 | 区分模拟时间和实际耗时 |

图像和公开日志不能夹带故障标签，文件名不编码正确答案。渲染器根据世界状态生成观测，不根据 Agent 的结论决定是否显示正常。

## 7 多源感知和经济优先级

优先复用设备已有可读取数据，而非为了多模态增加所有传感器。PLC 和驱动器中的电流、扭矩、状态与历史日志可用于部分状态监测，具体采样与语义仍需核对。[Siemens 资料](https://assets.new.siemens.com/siemens/assets/api/uuid%3Af13aaaa1-622e-4633-9074-f9e48690a16a/dics-b10144-00-7600best-practices-in-condition-monitoring-for-multi-axis-equipment-144.pdf)

| 输入 | 主要用途 | 完整项目接入计划 |
| --- | --- | --- |
| RGB 图像和视频 | 胶路、液位、卡料、跑偏、滴漏与定位 | 共用图像接口与任务插件 |
| 压力、流量、真空 | 点胶、灌装、气动、泵和冷却 | 明确测点、单位和采样时间 |
| 电流、扭矩、PLC 状态与日志 | 负载、动作、报警和节拍 | 区分低频趋势与高频故障诊断 |
| 振动与温度 | 旋转设备状态与工况 | 带测点、转速和负载的信号分析 |
| 热像 | 空间热点和加热过程 | 辐射测温数据、测量配置与标定 |
| 声学和超声 | 泄漏和声源定位等 | 音频或多通道波形及阵列信息 |
| 三维 | 体积、高度、间隙、平面度与姿态 | 深度、点云或标定双目数据 |
| 油液与润滑 | 污染、进水和磨损相关线索 | 传感器或检测报告适配 |

热像、声学和三维扩展需要对应传感器与测量配置；增加计算芯片不能产生原本没有采集的物理信息。纯软件阶段可采用录制或合成输入，明确标记来源。[ifm 设备健康资料](https://www.ifm.com/us/en/us/asset-health/asset-health-management)

## 8 视觉与光学计算路线

常规软件承担视频处理、检测、分割、跟踪和测量，按任务使用可替换运行时。光学计算首先采用 [Neuroptica](https://github.com/fancompute/neuroptica) 功能仿真，研究小型区域判别、特征变换和任务质量受参数误差影响的情况。

共同参考为幅度编码后通过参数化传递矩阵，再进行强度读出和共同数字后处理。仿真与软件参考使用一致的编码和数学关系。先验证理想状态，再加入有记录的参数偏差。任意模型层不默认能映射到光学网络。

长期路线包括扩大可映射算子、硬件感知模型适配、校准策略、误差与质量评估、任务分配及真实硬件验证。可继续评估 Photontorch、TorchONN 和 ScopeX SimPhony，但分别区分电路仿真、模型训练与架构性能估算。

电脑仿真的墙钟时间、模拟数值误差、预测硬件开销和实体芯片测量分别报告。只有获得真实硬件全流程结果后，才判断光计算是否带来计算或经济优势。

## 9 多 Agent 和快速响应

采用确定性协调器维护状态与约束，按需调用诊断 Agent、规划 Agent、验证 Agent，并在复杂任务中增加设备专家和资源协作角色。角色可以共享基础模型，简单任务不启用不必要协作。

诊断负责选择补证据和检验假设，规划负责比较处置与资源方案，验证负责依据新观测判定恢复或移交。有限动作集与程序约束不意味着把完整正确路径提前写死。

快速路径由受控规则或小型策略处理明确条件下的允许动作。语言模型在事件和步骤级工作。对话中快速选择模型名称仍未确认，保留接口，不预先绑定 REV 等未经确认的模型。

## 10 运行管理

| 子模块 | 管理内容 | 典型行为 |
| --- | --- | --- |
| 健康管理 | 数据、相机、后端、服务和工具 | 检测过期、失联和退化 |
| 事件管理 | 去重、关联、状态、超时和持久化 | 恢复未完成事件，维护终态 |
| 队列调度 | 并发、预算、截止时间和优先级 | 排队、取消与限制重试 |
| 资源管理 | 人员、备件、备用设备和时段 | 预约、冲突检测和重排 |
| 动作管理 | 权限、参数、前置条件、有效期和幂等 | 拒绝不适用动作，查询不明结果 |
| 监控审计 | 证据、工具、费用和终态 | 可读轨迹与停止开关 |

设备运行状态、服务健康状态和事件处置状态独立建模。相机重新在线不证明设备恢复；工单已接收不证明维修完成。事件可回到取证或规划，但受时间与预算限制。

## 11 统一对象与扩展合同

共用对象包括 Event、Observation、Evidence、Hypothesis、BackendCapability、ActionRequest、ActionResult、Verification、WorkOrder 和 Reservation。它们保存设备、测点、时间、来源版本、单位、质量、前置条件和状态版本。

新增场景包声明设备拓扑、数据源、感知与计算能力、知识、工具、恢复标准和测试。新增模态保留原始波形或几何结构，不强制转成图像；新协议和新任务通常仍需适配器或模型。

## 12 真实系统和业务连接器

在软件闭环稳定后，逐步连接只读设备数据、工单、备件、排程与生产系统。真实写操作需要具体站点权限、设备前置条件和现场验证。硬实时控制和安全联锁由对应控制系统承接。

首选 FUXA 工作台与 Mosquitto 消息代理；ThingsBoard、Atlas CMMS、Frigate 和 Node RED 为后续参考适配对象，不要求同时部署。每个集成记录能力、版本、授权和安装约束。

## 13 数据、评测与模型更新

合成数据用于受控验证，公开数据用于感知参考，真实试点用于检验现场泛化。开发、保留和发布回归数据分别管理。根因真值、动作效果与图像标签不混为同一种标注。

比较固定规则、单 Agent 与按需多 Agent，保证任务、工具和总预算可比。分别评估感知质量、正确终态、误处置、调用成本、等待时间和适配工作量。无依据的未知与错误确定诊断分开计数。

长期知识积累来自经确认的事件结果；模型与策略更新先离线回归、版本化发布，再观察现场结果，不让未经验证的新模型自动替换生产路径。

## 14 兼容性定义与范围

兼容性分为接口可表达、感知有效、业务接入、执行闭环与实际效果五层。统一接口覆盖任务表达，不自动代表模型识别、根因诊断或设备修复能力。

本次 30 类候选中，23 类以 RGB 为主要入口，5 类需要专门成像或补充测量，2 类偏运行与资源调度。这是等权候选分类，分别为 76.7%、16.7%、6.7%；并非行业覆盖率或当前通过率。整个设备运维领域尚无可用总体和代表性验证，不能估计覆盖百分比。

| 阶段 | 工作目标 | 进入下一阶段的证据 |
| --- | --- | --- |

| 多模态和资源 | 振动、温度等与维修排程 | 多源证据与资源约束下有效 |

## 16 比赛版本如何截取

比赛版本是完整项目中“夜班异常核实与处置”这一工作流的独立验证。保留点胶主闭环、灌装兼容性测试、失败恢复与审计；其他模态、真实工厂、多节点和硬件性能研究进入完整路线图。

两个仓库独立初始化、独立记录原创贡献。赛前只存规划、提示词草案和资料。比赛代码在正式 72 小时内编写，不从完整项目复制赛前实现。赛后再按许可和来源记录将验证成果回收至完整平台。

比赛仓库当前按用户要求保持私有。最终提交公开仓库的官方要求已经记录；不会在没有后续授权的情况下改变当前可见性。

## 17 风险与产品决策

主要风险是缺少真实根因数据、模拟与现场差距、设备语义不一致、多 Agent 成本、光学模型适配和平台集成工作量。通过可检查的证据、分阶段验证、共同参考、按需协作和真实试点解决，不用扩大兼容性表述来掩盖未验证能力。

当前确定技术方向，尚未部署系统。需要确认团队、电脑配置、模型 API 与预算、试点设备和后续数据权限。

## 18 三十类候选场景

完整清单和数据边界见 docs/SCENARIOS.md。本文件下方附同一清单，便于独立阅读。

### 候选任务清单

场景编号沿用规划讨论。协作链路为拟议设计，尚未实现验证。RGB 表示主要视觉入口，仍可能需要过程数据确认原因。

## 01 输送带跑偏

- 输入类型：RGB。
- 观察任务：分割带体边缘并相对机架测偏移。
- 协作和动作：查负载与历史；选择模拟减速或调整；新帧复核。
- 数据与边界：录像或合成偏移，设备拓扑与日志需配置。

## 02 输送带撕裂与接头开裂

- 输入类型：RGB。
- 观察任务：检测损伤并跨周期追踪。
- 协作和动作：排除污渍；关联带体记录；安排检修与损伤复查。
- 数据与边界：真实裂纹可作视觉输入，发展过程与维修结果需单独构建。

## 03 托辊卡滞与轴承温升

- 输入类型：补充模态。
- 观察任务：视频转动迹象结合热像或振动。
- 协作和动作：对比负载与邻近部件；定位维修对象。
- 数据与边界：RGB 单独不足以完成温升诊断，需要热像或其他信号。

## 04 输送工件堆积与上下游卡料

- 输入类型：RGB。
- 观察任务：跟踪速度 间距 积压区域。
- 协作和动作：关联上下游；调整模拟供料与缓存；验证恢复。
- 数据与边界：扩展主场景；需要有状态的多工位模拟器。

## 05 振动盘或料斗堵料

- 输入类型：RGB。
- 观察任务：出口流量 可见料位与姿态。
- 协作和动作：区分缺料和堵料；查电流参数；测试恢复。
- 数据与边界：视频与合成过程日志；遮挡时需补充传感器。

## 06 机器人吸盘漏吸或掉件

- 输入类型：RGB。
- 观察任务：抓取后工件存在与滑移。
- 协作和动作：查真空压力；排查姿态和供气；选择重试或维修。
- 数据与边界：视觉判断抓取结果，原因仍需压力与设备证据。

## 07 夹具未夹紧与定位不到位

- 输入类型：RGB。
- 观察任务：相对基准测工件位置。
- 协作和动作：查行程压力；判断可否继续；重新定位后复核。
- 数据与边界：图像偏移可合成，真实夹紧力不能由外观代替。

## 08 紧固件松动迹象

- 输入类型：RGB。
- 观察任务：缺失 间隙 防松标记错位。
- 协作和动作：关联紧固位置；安排检查；对比维护前后。
- 数据与边界：图像仅给出检查线索，不能证明实际扭矩。

## 09 CNC 刀具磨损与崩刃

- 输入类型：RGB。
- 观察任务：刀刃局部图像和磨损测量。
- 协作和动作：融合力 振动与加工记录；安排换刀并复核。
- 数据与边界：MATWI 可提供图像与信号；需专用成像与加工域验证。

## 10 点焊电极端面磨损

- 输入类型：RGB。
- 观察任务：电极轮廓和端面变化。
- 协作和动作：关联使用与焊接记录；选择修磨或更换。
- 数据与边界：需受控投影或测量成像；外观不替代焊接完整质量检验。

## 11 灌装嘴堵塞 滴漏与液位异常

- 输入类型：RGB。
- 观察任务：液位测量 瓶口残液与滴漏。
- 协作和动作：关联灌装头；查询阀与压力；切换或检修并复检。
- 数据与边界：必做主场景；透明度和视角限制需在数据中体现。

## 12 旋盖头打滑与高度偏移

- 输入类型：RGB。
- 观察任务：盖倾斜 到位与间隙。
- 协作和动作：追溯旋盖头；查扭矩换型；沙盒测试并复核。
- 数据与边界：外观不能直接确定密封性或实际扭矩。

## 13 热封夹爪污染与封口异常

- 输入类型：RGB。
- 观察任务：封口褶皱 夹料 断续。
- 协作和动作：查温度 压力 速度；安排清洁或检查；追溯复检。
- 数据与边界：外观不能替代密封性能测试；温度原因需补证据。

## 14 贴标机辊轮打滑与定位异常

- 输入类型：RGB。
- 观察任务：标签位置 角度 褶皱与漏贴。
- 协作和动作：区分配方和机械来源；查编码器；测试校正。
- 数据与边界：可控图像合成；需真实工位映射支持追因。

## 15 喷码机喷头堵塞与缺字

- 输入类型：RGB。
- 观察任务：OCR 和固定断笔分布。
- 协作和动作：排除相机问题；查墨路清洗；圈定批次与复检。
- 数据与边界：缺损可合成；噪声与模糊应为反例。

## 16 点胶堵塞 拉丝与出胶不稳

- 输入类型：RGB。
- 观察任务：胶路分割 宽度与断点。
- 协作和动作：查供胶压力与轨迹；测试 清洗或维修；验证新胶路。
- 数据与边界：必做主场景；湿亮胶路与反光需额外测试。

## 17 喷涂堵塞与喷幅不均

- 输入类型：RGB。
- 观察任务：条纹 漏喷与覆盖分布。
- 协作和动作：对应喷嘴；查压力与材料；安排检查。
- 数据与边界：外观只作线索；真实厚度和工艺原因需补充测量。

## 18 贴片机吸嘴异常与位置漂移

- 输入类型：RGB。
- 观察任务：元件缺失 旋转与位移。
- 协作和动作：关联吸嘴 供料器与元件；沙盒禁用并复检。
- 数据与边界：需贴装日志；缺陷图不能独立确定根因。

## 19 锡膏印刷钢网堵孔与刮刀异常

- 输入类型：补充模态。
- 观察任务：可见缺陷分布；体积检查需三维数据。
- 协作和动作：比较固定位置与全局偏移；查清网与定位记录。
- 数据与边界：首版 RGB 可作外观演示，完整体积判定需 3D SPI。

## 20 卷对卷辊面损伤与周期缺陷

- 输入类型：RGB。
- 观察任务：重复压痕划伤与间距。
- 协作和动作：线速换算周期；对照辊径布局；检查可疑辊。
- 数据与边界：周期关联是排查线索，不能自动证明唯一原因。

## 21 冷却管路可见泄漏与积液

- 输入类型：RGB。
- 观察任务：分割液体扩展与位置。
- 协作和动作：结合管路拓扑 流量压力；沙盒切换支路并建单。
- 数据与边界：反光与透明水体困难；泄漏源需额外证据。

## 22 泵密封泄漏与油液渗漏

- 输入类型：RGB。
- 观察任务：滴漏 油污变化与历史对比。
- 协作和动作：区分旧污渍；查压力振动；预约检查。
- 数据与边界：时间序列和其他信号支持诊断；液体性质不可只凭颜色确认。

## 23 电机减速箱异常温升

- 输入类型：补充模态。
- 观察任务：热像热点与负载变化。
- 协作和动作：融合振动负载；选择检查与维修窗口。
- 数据与边界：热像为主要输入；单张温度图不能确定原因。

## 24 配电柜端子局部过热

- 输入类型：补充模态。
- 观察任务：热像局部温差与回路位置。
- 协作和动作：对照电流和资产影响；生成检查工单。
- 数据与边界：需要热像与电气证据；沙盒不做实体带电维修。

## 25 压缩空气或真空泄漏

- 输入类型：补充模态。
- 观察任务：声学热点与设备位置。
- 协作和动作：融合气路流量；按影响和成本安排检修。
- 数据与边界：普通 RGB 一般看不到泄漏；需声学或流量等数据。

## 26 镜头污染与缺陷误报

- 输入类型：RGB。
- 观察任务：跨产品固定图像坐标污斑。
- 协作和动作：对比相邻视角；判定观测质量；清洁或切换并验证。
- 数据与边界：跨场景故障测试；不能只凭固定位置排除全部真实缺陷。

## 27 照明老化 频闪与局部失效

- 输入类型：RGB。
- 观察任务：亮度漂移 条带与暗区。
- 协作和动作：查曝光与光源；测试备用光源；复核质量。
- 数据与边界：容易合成；曝光变化和真实材料变化应作反例。

## 28 相机支架松动与标定失效

- 输入类型：RGB。
- 观察任务：基准点和整个视野变化。
- 协作和动作：区分换型；重标定并用保留图验证。
- 数据与边界：二维几何场景适合原型；三维标定需额外方法。

## 29 推理服务变慢 丢帧与积压

- 输入类型：运行调度。
- 观察任务：时间戳 延迟 队列和输出质量。
- 协作和动作：定位瓶颈；改变抽帧或后端；检查延迟和任务质量。
- 数据与边界：跨场景故障测试；主要依赖运行日志。

## 30 多产线告警与维修资源冲突

- 输入类型：运行调度。
- 观察任务：多设备事件证据与状态。
- 协作和动作：设备 Agent 提交需求；协调人员备件与停机窗口。
- 数据与边界：适合多 Agent；需独立排程约束与结果评价。
