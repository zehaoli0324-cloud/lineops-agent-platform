# 首版实施规格与验收

版本 0.1 · 2026-11-16 · 此文件定义预期行为；实现状态见 STATUS.md（完整项目）或比赛时间边界。

## 1 具体交付与非目标

完整平台首版用两条软件产线验证：同一运行服务和工具协议能否处理点胶与灌装的不同观测、故障与动作。点胶是主路径，灌装是第二种任务。工作台分为独立证据页和待配置 FUXA。首版不含 PLC 写入、真实设备维修、真实产线部署和光学硬件测速。

## 2 可切换的契约

| 对象 | 必需内容 | 约束 |
| --- | --- | --- |
| Scenario | id、measurement、thresholds、manual、allowed_actions | 场景负责语义，运行器不读取私有故障 |
| Observation | id、scene、version、frame、telemetry、quality | 帧与参数属于同一状态版本；缺失不能填为正常 |
| Measurement | frame_id、metric、value、quality | 由像素测量，不读取故障真值 |
| Action | action_id、name、expected_version、expires_at | 白名单；维护前暂停；有效期；幂等 |
| Receipt | action_id、accepted、before_version、after_version、reason | 工具失败保留原因；不自动标记恢复 |
| Incident | id、scene、status、mode、started_at、trace | recovered / handed_off / stopped / failed 分开 |
| Work order | id、incident_id、reason、status | 创建工单代表移交，不代表恢复 |
| Backend result | backend、input、output、reference_error、fallback | 小型数值变换不等于工业视觉模型或真实芯片 |

## 3 有状态模拟与故障因果

| 条件 | 点胶观测 | 灌装观测 | 有效响应 | 无效响应 |
| --- | --- | --- | --- | --- |
| normal | 胶条覆盖率接近 1，供压正常 | 液位接近 1，供压正常 | 读取并验证 | 不必要维护 |
| clog | 覆盖率偏低，供压正常 | 液位偏低，供压正常 | 暂停→清理→恢复→新观测 | 补充供料 |
| supply | 覆盖率偏低，供压低 | 液位偏低，供压低 | 暂停→补充→恢复→新观测 | 清理喷嘴 |
| camera | 图像质量不合格，过程参数正常 | 图像质量不合格，过程参数正常 | 暂停→清理镜头→恢复→新观测 | 把无效图像判成修复 |
| persistent | 观测不合格，维修无效 | 观测不合格，维修无效 | 工单移交，保持暂停 | 反复维修到超预算或宣称恢复 |

首版是简化离散因果模型，不宣称物理保真。故障注入 API 属于操作者控制面；Agent 工具层没有故障名称、世界对象或文件系统访问。

## 4 生命周期与网关

事件路径：created → running → recovered / handed_off / stopped / failed。每个步骤保存角色、工具参数、返回值和序号。暂停与恢复修改设备版本。维修必须暂停且观测版本仍有效。相同 action_id 与相同参数返回首次回执；同 ID 不同参数拒绝。拒绝动作不修改设备。网关只接受已列举动作，模型不能执行 shell 或任意 HTTP。首版单进程设备锁串行化运行，跨进程锁列入下一阶段。

恢复谓词：连续三次新采集（不同帧 ID）的有效图像测量均在场景阈值内，供压与过程状态合格，设备已运行。至少一次新观测发生在最后状态变更后。三帧是首版采样检查，不代表工业统计置信度；物理时间稳定窗口后续实现。模型说“已修复”不能越过此谓词。

移交谓词：已创建工单、设备暂停、记录未解决证据。停止谓词：预算耗尽或人工停止；保留状态与轨迹。工具异常、协议错误或模型请求错误应生成 failed 事件和可追踪原因。

## 5 Agent 与离线对照

诊断角色只能读取图像测量、遥测和手册；规划角色可提交白名单动作和工单；验证角色读取动作后新观测并提交验证。模型输出 function tool_calls 后，运行器执行并以 tool 消息回传，再由模型决定下一步。多个角色可以共用同一个模型端点。角色切换由运行器完成，不把角色提示词轮转本身算作能力。

离线规则对照用同一公开工具层、网关与恢复谓词，不用隐藏真值；用于无密钥复现和回归测试。运行记录标明 mode=offline 或 llm。接通端点和协议单测通过不等于真实模型效果验证。

## 6 评测设计

两种场景 × 五种条件形成十个固定任务。报告每个任务的恢复、移交、停止、失败、动作数、总工具数和耗时，不把移交算恢复。另测维护前置条件、过期、陈旧版本、幂等重放、同 ID 不同参数、误报恢复、持久故障、模型协议与工具越权。后续扩展随机种子、噪声、传感器缺失、重启恢复、跨设备资源争用与未见故障。

兼容性证据首先是两条产线在同一服务下完成相同契约；30 个目录场景均需独立数据、标定和验收。不能据此推导“覆盖智能运维领域百分之多少”。

## 8 运行方式和时间边界

完整项目可以从现在开始实现。比赛项目在正式开发窗口前只存设计、官方规则来源、第三方指针，不复制完整项目的模拟器、适配器、评测或工作台实现。比赛窗口以最终官方 brief 为准；提交公开性与来源声明按最终要求处理，当前保持私有。
